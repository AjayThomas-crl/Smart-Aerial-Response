Architecture 1 · Smart Aerial Response as a smart-city service

City data in, one coordinated drone mission per base out, run from the Integrated Command and Control Centre (ICCC)

Layer 1

City data sources

Satellite flood mapsSentinel-1 / Sentinel-2 flood extent (ESA), map image of the city
Live weatherOpen-Meteo API: rainfall (mm), wind speed and direction
City GIS referenceImage-centre latitude/longitude, map scale or GeoTIFF
Operator inputA few clicks on flood pixels at the command centre

Layer 2 · intelligence

Swarm planner A.D.A.P.T. core

Flood perceptionHSV colour sampling, morphology, flood zones (contours)
Flood-spread forecastRain grows and wind shifts the flood over a 2 h horizon → no-fly obstacle field
Multi-base swarm planningDry base selection (≤ 6), drop-to-base territories, D* Lite routing, battery and payload sorties
Airspace deconfliction + validationRoute-crossing check and repair, battery re-check on routed path, mission file validator

Layer 3

Execution

Mission filesOne QGC WPL 110 file per drone (take-off, drops, servo release, RTL)
Ground controlQGroundControl / Mission Planner, ArduPilot SITL for testing
UAV swarmOne drone per base, own territory, routes never cross
D1D2D3D4D5D6

Layer 4

City command centre

Live swarm dashboardDrone status, battery, kits delivered, mission clock
Relief to citizensFood, water, medicine kits dropped at the dry edge of each flood zone
Hand-off to ground teamsUnreachable points sent to NDRF / boat teams
SDG reportingSDG 11.5, 13.1, 9.1, 3.d
↻ Re-planning loop

New satellite pass or weather update → the planner is run again in about a minute → new bases, routes and mission files go out. The swarm is coordinated before each flight; drones do not need to talk to each other in the air.
